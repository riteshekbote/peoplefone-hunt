## LEAD 2: OAuth arbitrary redirect_uri / implicit-token theft (client_id=1)

**Assets:** auth.peoplefone.com/oauth/authorize + /oauth/token + portal.peoplefone.ch

| Gate | Verdict | Reason |
|---|---|---|
| Q1 Scope | YES | auth.peoplefone.com + portal.peoplefone.ch are in-scope ("All company-owned infrastructure… customer portals… domains operated by peoplefone GmbH") |
| Q2 Reachable | YES | OAuth authorize endpoint publicly accessible without any authentication. GET /oauth/authorize?client_id=1&redirect_uri=https://evil.com → HTTP 302 → /de_CH/login with attacker redirect_uri PRESERVED. Fully unauthenticated reachability confirmed. |
| Q3 Impact | YES | If public/PKCE client: full ATO of any portal user (recordings, CDR, PBX, billing, SMS, PII). Even if confidential: confirmed open-redirect on login flow + login-CSRF. CRITICAL severity. |
| Q4 Non-invasive proof | YES | Passively confirmed: 302 redirect preserving arbitrary redirect_uri through login flow. Implicit AND PKCE params accepted and preserved. /oauth/token returns 405 (endpoint exists). All observable without login or token. |
| Q5 Novel | YES | Bigpickle reversed its own prior REJECTED verdict when new evidence appeared. No prior report evidence. |
| Q6 Not rejected | YES | Not on always-rejected list. |
| Q7 Reasonable triager | YES | Redirect_uri bypass demonstrable via passive HTTP observation. 302 preserving attacker-controlled redirect_uri through real login page is concrete, exploitable primitive. |

### VERDICT: VALID

**Minimal read-only proof steps:**
1. GET https://auth.peoplefone.com/oauth/authorize?client_id=1&redirect_uri=https://attacker.example.com/callback&response_type=code&scope=openid&state=test123 → observe HTTP 302 → /de_CH/login with redirect_uri preserved
2. Confirm implicit flow: response_type=token accepted and preserved through same 302
3. Confirm PKCE flow: code_challenge+code_challenge_method=S256 accepted and preserved
4. GET https://auth.peoplefone.com/oauth/token → HTTP 405 (confirms live token-exchange endpoint)

**Impact:** Open redirect primed on real login flow + login-CSRF; full ATO if public/PKCE client.

**CVSS 3.1:** AV:N/AC:L/PR:N/UI:R/S:C/C:H/I:H/A:N → 9.1 CRITICAL (if public client; else 7.4 HIGH for open-redirect + login-CSRF)

**Reporting channel:** bugs.olivermaicher.eu (Oliver Maicher private program) — report + PoC + contact + payment. Include HTTP 302 trace showing redirect_uri preservation and 405 on /oauth/token.
